# 本地数据加密备份

## 数据范围

备份包含当前本地 SQLite 快照 `mogo.db`，以及存在时的单用户资料 `user-profile.json`。明文数据只在 C++ 后端内存和受控临时目录中出现，Web 与 React Native JS 只接收 `MOGO-BACKUP/1` 加密文本。

SQLite 使用 `sqlite3_backup` 生成一致性快照，兼容 WAL；导入前对解密出的数据库执行 `PRAGMA quick_check`，资料 JSON 校验格式版本。覆盖恢复前会保存数据库和 JSON 回滚副本，任一步骤失败都尝试恢复原文件。

## 加密格式

- 密码要求：前端按至少 8 个字符校验，后端限制为 8 至 1024 个 UTF-8 字节。
- 密钥派生：Argon2id，19 MiB 内存、2 次迭代、单 lane、16 字节随机 salt。
- 认证加密：XChaCha20-Poly1305，24 字节随机 nonce。
- 文件封装：`MOGO-BACKUP/1` 文本头加 Base64 密文；二进制头、salt、nonce 和明文长度均作为附加认证数据。
- 大小限制：解密后的备份容器最多 256 MiB；客户端选择文件最多 350 MiB。

密码错误、认证标签不匹配和文件被篡改使用同一个 `BACKUP_DECRYPT_FAILED` 错误，不区分具体原因。密码不持久化，也没有找回机制。

## 冲突策略

| 策略 | 行为 |
| --- | --- |
| `OVERWRITE` | 用备份覆盖本地 SQLite 和备份中包含的资料 JSON；恢复失败时回滚。 |
| `KEEP_EXISTING` | 已存在的本地文件保持不变，只导入缺失文件。 |

不做逐行 `INSERT OR IGNORE` 合并，因为跨表主键冲突可能让消费、分类、指标和交易记录指向错误实体。后续如需合并，应由各业务 feature 提供显式、可迁移的领域合并策略。

## 版本演进

加密外层和明文容器都带独立版本。新增本地持久化文件时，应添加稳定 entry 名称、导入校验与回滚测试；不应复用现有版本改变字段语义。无法识别的版本或 entry 必须拒绝导入，不能静默忽略。
